# 资源与实测

机器2逻辑核，实际内存约1613MiB，与TaskFlow共存。web限制256MiB/0.5CPU，worker及FFmpeg合计限制512MiB/1CPU；一个任务串行执行。探针每2秒采集宿主机MemAvailable，只读挂载指标目录。
准入条件：主机可用内存≥200MiB、磁盘剩余≥5GiB、指标≤30秒。容器还检查cgroup余量；对inactive_file可回收文件缓存作扣除，避免刚加载镜像产生的缓存被误当成不可回收内存。硬上限始终由容器执行。

|样本|耗时|主机最低可用内存|worker cgroup历史峰值|
|---|---|---|---|
|15秒720p，3镜头|16.65秒|758.19MiB|448835584字节，约428MiB|
|60秒720p，12镜头|58.20秒|735.71MiB|464367616字节，约443MiB|

样本使用PNG测试图片、WAV提示音、中文ASS字幕及AAC音轨，包含排队轮询时间。cgroup峰值包含文件缓存，是容器启动以来峰值，不是单个FFmpeg进程RSS。数据见integration-results.json。
两次测试期间TaskFlow健康检查始终正常。未测长时间连续压测、真实配音供应商、真实照片复杂解码或多人高并发；测试结果不作容量外推。首版每个用户2个活动任务、全局10个，超出拒绝入队。
