# 资源限制与实测

适用应用版本 `adbb539`。镜序面向单机低并发环境。Web 提供 API，独立 Worker 串行处理媒体和模型任务，FFmpeg 计入 Worker 资源限额。

| 项目 | Compose 配置或准入阈值 |
|---|---|
| Web | 256 MiB / 0.5 CPU |
| Worker 和 FFmpeg | 512 MiB / 1 CPU |
| 主机磁盘 | 可用空间至少 5 GiB |
| 主机内存 | 指标报告可用内存至少 200 MiB |
| 采样 | 约每 2 秒更新，准入时数据需在 30 秒内 |
| 容器内存余量 | cgroup 有上限时，将 `inactive_file` 计入可回收空间，至少留 64 MiB |
| 任务上限 | 每用户最多 2 个活动任务，全局最多 10 个 |

主机指标目录只读挂载。准入失败时先查探针时间、磁盘和内存。模型调用还受供应商账号额度、平台调用次数及存储配额约束。[准入代码](../backend/core/queue.py) · [Compose 配置](../docker-compose.yml)

## 2026-11-06 本地合成基线

基线机器约 2 逻辑核、1613 MiB 内存，与 TaskFlow 共用服务器。样本由 PNG、提示音、ASS 字幕和 AAC 音轨组成，耗时包含排队轮询。

| 样本 | 耗时 | 主机最低可用内存 | Worker cgroup 历史峰值 |
|---|---:|---:|---:|
| 15 秒 720p，3 分镜 | 16.65 秒 | 758.19 MiB | 约 428 MiB |
| 60 秒 720p，12 分镜 | 58.20 秒 | 735.71 MiB | 约 443 MiB |

cgroup 历史峰值包含文件缓存。测试期间原有服务健康。真实照片、网络排队和模型等待时间由素材与供应商决定，上述数字用于比较这组固定样本。[原始运行数据](integration-results.json) · [当前发布验收](test-report.md)
